# دليل الحزمة — إيه جديد، إيه هيتغيّر، إيه هيفضل زي ما هو

## 📁 هيكل الفولدرات في الحزمة دي

```
final_package/
├── PROJECT_STATUS.md              ← اقرأيه الأول، فيه الملخّص الشامل
├── 0_complete_backend_full_copy/  ← نسخة كاملة مستقلة من الباك اند بالكامل
├── 1_backend_updates_only/        ← تحديثات على فولدرك الموجود بس (لو مفضّلة تستبدلي ملفين بس)
├── 2_supporting_systems_new/      ← أنظمة جديدة، فولدر جديد تماماً
├── 3_flutter_handoff/             ← للتسليم لزميلك مباشرة
└── 4_react_reference_ui/          ← نسخ تجريبية، مش للنشر
```

---

## 0️⃣ `0_complete_backend_full_copy/` → **نسخة كاملة مستقلة، بديل لفولدرك الحالي بالكامل**

لو حبيتِ تبدئي بفولدر نضيف تماماً بدل ما تستبدلي ملفات في الموجود، ده نسخة كاملة 100% (كل الموديلات الـ17، بيانات الطلاب، التوثيق) — تقدري تستخدميه بدل `combined_deploy_package` القديم بالكامل، أو تتجاهليه وتستخدمي القسم 1 بس لو مبسوطة من الموجود عندك.

⚠️ **مفيش فيه `key.env`** (اتشال عمداً لأسباب أمان) — لازم تضيفي بتاعك بنفسك زي المعتاد.

---

## 1️⃣ `1_backend_updates_only/` → **تستبدلي بيها الموجود في `combined_deploy_package`**

| الملف | الحالة | فين يروح بالظبط |
|---|---|---|
| `combined_app.py` | 🔄 **يستبدل** الموجود عندك | جذر `combined_deploy_package/` |
| `next_term_gpa_model.joblib` | ✨ **ملف جديد** | جوه `combined_deploy_package/ml_models/` |

**بعدها:** `git add . && git commit -m "..." && git push origin main` (زي المعتاد)

---

## 2️⃣ `2_supporting_systems_new/` → **اعملي فولدر جديد بجانب `combined_deploy_package`**

اقترح تسميه `supporting_systems`، وحطّي فيه الملفين دول. **مستقلين تماماً عن الباك اند الرئيسي** — بورتات مختلفة (5001، 5002)، مش هيتعارضوا مع حاجة.

| الملف | يعمل إيه | تشغّليه إمتى |
|---|---|---|
| `mock_features_server.py` | بيانات وهمية موسومة (Progress/Notifications/Attendance/Assignments/Exams) لتجربة شكل الشاشات في Flutter | لو عايزة تشوفي شكل الشاشات دي قبل ما البيانات الحقيقية تتجمّع |
| `engagement_tracker.py` | قاعدة بيانات حقيقية **فاضية تماماً**، هتتملى فعلياً مع الاستخدام الحقيقي | **شغّليها من دلوقتي** — كل يوم بيعدّي من غيرها يوم بيانات حقيقية ضايعة |
| `mock_data_preview/` (فولدر فرعي) | عيّنة ثابتة من نفس بيانات `mock_features_server.py` كملفات JSON، للمراجعة السريعة بدون تشغيل بايثون | اختياري تماماً، مش جزء من تشغيل النظام |

---

## 3️⃣ `3_flutter_handoff/` → **سلّميها لزميلك زي ما هي**

مفيش أي تعديل مطلوب منك — الملفين دول جاهزين للاستخدام المباشر في مشروع Flutter.

| الملف | المحتوى |
|---|---|
| `analytics_api_client.dart` | كل الـmodels والدوال لكل الـendpoints (بما فيهم الجديد) |
| `API_DOCUMENTATION.md` | شكل كل طلب/رد بالتفصيل |

---

## 4️⃣ `4_react_reference_ui/` → **اختياري، للمرجعية بس**

دول نسخ React جرّبناها محلياً للتأكد إن الباك اند شغّال صح. **مش هتتنشر ومش جزء من التطبيق النهائي** (اللي هيبقى Flutter). سيبيها في فولدر منفصل لو حبيتِ ترجعيلها كمرجع بصري بس.

---

## ✅ إيه اللي **مش** هيتغيّر خالص

- كل ملفات الباك اند التانية (`requirements.txt`, `Procfile`, `key.env`, `student_data/`, باقي `ml_models/`) — **زي ما هي، من غير أي لمسة**
- الرابط المنشور على Render — نفسه، هيتحدّث تلقائياً بعد الرفع
- ريبو GitHub — نفسه، مش محتاجة ريبو جديد

## الترتيب المقترح للتنفيذ

1. حدّثي `combined_app.py` + الموديل الجديد (القسم 1) → ارفعيها Git
2. شغّلي `engagement_tracker.py` (القسم 2) → سيبيها شغّالة في الخلفية
3. ابعتي فولدر `3_flutter_handoff` لزميلك
4. `4_react_reference_ui` سيبيها جنب، تفتحيها وقت الحاجة بس
